--- ## 1. Теоретический аудит протокола SMB и модели OSI
В рамках данной лабораторной работы исследовался протокол **SMB (Server Message Block)** — проприетарный сетевой протокол компании Microsoft, предназначенный для удаленного доступа к файлам, принтерам и другим сетевым ресурсам.

### 1.1. Взаимодействие уровней модели OSI
Согласно сетевой архитектуре, изученной по ходу подготовки к атаке:
* **7-й уровень (Прикладной / Application Layer):**
На этом уровне функционирует сам протокол SMB, предоставляя интерфейс для программного взаимодействия с файловой системой удаленного сервера.
* **4-й уровень (Транспортный / Transport Layer):**
В современных системах (начиная с Windows 2000) SMB инкапсулируется напрямую в стек протоколов TCP/IP, используя выделенный **порт 445** (имя службы: `microsoft-ds`).
В устаревших архитектурах SMB опирался на протокол NetBIOS поверх TCP/IP (NBT), задействуя порты `137, 138, 139`.

### 1.2. Физика уязвимости Security Misconfiguration (Null Session)
По умолчанию протокол SMB требует строгой аутентификации (проверки пары логин/пароль) для предоставления доступа к общим сетевым папкам (Shares).
Однако из-за человеческого фактора и халатности системного администратора на целевом хосте активирован **гостевой доступ / нулевая сессия (Null Session / Guest Authentication)**. Данная уязвимость конфигурации позволяет неавторизованному внешнему атакующему подключиться к службе с абсолютно пустыми учетными данными (`username: "", password: ""`) и перечислить структуру внутренних каталогов сервера.

--- ## 6. Рекомендации по устранению уязвимостей (Remediation)
1. **Отключение гостевого доступа к каталогу:** В свойствах сетевой паки `WorkShares` (вкладка «Доступ» -> «Разрешения») принудительно удалить встроенные группы `Все` (Everyone) и `Гость` (Guest). Доступ должен предоставляться строго авторизованным доменным пользователям по принципу наименьших привилегий.
2. **Блокировка Null Session на уровне ОС:** Через Редактор локальной политики безопасности (`secpol.msc`) активировать параметры «Сетевой доступ: запретить анонимное перечисление учетных записей SAM» и «Сетевой доступ: запретить анонимное перечисление общих ресурсов». В реестре Windows установить параметр `RestrictNullSessAccess` в значение `1`.
3. **Сетевое экранирование периметра:** На внешнем брандмауэре (Firewall) полностью заблокировать любые входящие подключения из внешней сети на порты `445` и `137-139`. Удаленный доступ к файловым ресурсам компании разрешить строго внутри защищенного корпоративного VPN-туннеля.
